# 03 - Data model

## Ticket

One JSON file per ticket. The same schema carries through every stage; skills
add fields as the ticket progresses and append to `history`.

```json
{
  "number": "INC0001",
  "created_at": "2026-09-29T09:12:00+09:00",
  "caller": "k.woraitthinan",
  "channel": "portal",
  "language": "en",
  "short_description": "Cannot access S3 bucket wora-test-s3",
  "description": "Access denied when listing objects in the dev bucket.",

  "state": "pending-action",
  "agent": "request-access",
  "confidence": { "grouping": 0.91, "action": 0.72 },
  "alternatives": [
    { "agent": "ops-automation", "score": 0.06 },
    { "agent": "service-desk",   "score": 0.03 }
  ],

  "runbook": "RB-014-s3-access.md",
  "plan": [
    { "tool": "aws_s3_get_bucket_policy", "write": false,
      "args": { "bucket": "wora-test-s3" } },
    { "tool": "aws_iam_attach_policy", "write": true,
      "args": { "role": "CMP001-dev-readonly", "policy": "S3ListDev" },
      "rollback": "detach policy S3ListDev from role CMP001-dev-readonly" }
  ],
  "evidence": "Bucket policy lacks s3:ListBucket for the caller's role.",

  "approval": { "required": true, "reason": "write-tool", "by": null, "at": null },

  "metrics": { "ai_seconds": 41, "human_wait_seconds": null, "tokens": 7680 },
  "run_id": "20260929-1712-INC0001",

  "history": [
    { "stage": "grouping", "at": "2026-09-29T17:12:03+09:00",
      "actor": "ai", "note": "routed to request-access (0.91)" },
    { "stage": "plan", "at": "2026-09-29T17:12:44+09:00",
      "actor": "ai", "note": "RB-014 matched; 1 write step requires approval" }
  ]
}
```

### Field rules

| Field | Rule |
|---|---|
| `number` | Immutable. Matches the filename |
| `state` | Must agree with the folder the file sits in |
| `agent` | Null until grouped. One of the five configured agents |
| `confidence.grouping` | Set by `ticket-grouping`, never changed afterwards |
| `confidence.action` | Set by the agent skill |
| `alternatives` | Populated at grouping; drives the Gate 1 buttons |
| `runbook` | Must name a real file in `knowledge/runbooks/` (REQ-010) |
| `plan[].write` | Mandatory on every step (REQ-012) |
| `plan[].rollback` | Mandatory when `write` is true (REQ-019) |
| `approval.reason` | One of `write-tool`, `low-confidence`, `low-grouping` |
| `metrics.human_wait_seconds` | Null until a human acts |
| `history` | Append-only (REQ-021) |

### States

| `state` | Folder |
|---|---|
| `new` | `data/01-inbox/` |
| `grouped` | `data/02-grouped/<agent>/` |
| `pending-grouping` | `data/03-approval/pending-grouping/` |
| `pending-action` | `data/03-approval/pending-action/` |
| `approved` | `data/03-approval/approved/` |
| `rejected` | `data/03-approval/rejected/` |
| `awaiting-info` | `data/04-awaiting-info/` |
| `escalated` | `data/05-escalated/` |
| `resolved` | `data/06-resolved/` |

## Run artifacts

`data/runs/<run-id>/` where run-id is `YYYYMMDD-HHMM-<number>`.

| File | Contents |
|---|---|
| `plan.json` | The proposed plan as offered, before any human decision |
| `retrieval.json` | Candidate runbooks with scores - the evidence trail |
| `decision.json` | `auto`, `approved`, `rejected`, `advisory` or `escalated`, with actor and reason |
| `trace.log` | Line-per-event log including token counts |

## board.json

Generated by `board-refresh`. Drives Overview and Review Queue.

```json
{
  "generated_at": "2026-09-29T17:20:00+09:00",
  "counts": { "unprocessed": 2, "needs_you": 4, "escalated": 2, "resolved_today": 22 },
  "auto_handled": { "count": 22, "total": 28, "rate": 0.79 },
  "tickets": [
    {
      "number": "INC0001",
      "state": "pending-action",
      "agent": "request-access",
      "short_description": "Cannot access S3 bucket wora-test-s3",
      "confidence": { "grouping": 0.91, "action": 0.72 },
      "alternatives": [ { "agent": "ops-automation", "score": 0.06 } ],
      "runbook": "RB-014-s3-access.md",
      "plan": [ { "tool": "aws_iam_attach_policy", "write": true } ],
      "approval_reason": "write-tool",
      "run_id": "20260929-1712-INC0001"
    }
  ]
}
```

`counts.needs_you` is the sum of both pending folders - it is the number shown
in the nav badge, because it is the only figure that demands action.

## stats.json

Generated by `board-refresh`. Drives Insights.

```json
{
  "generated_at": "2026-09-29T17:20:00+09:00",
  "window": "today",
  "rates": {
    "grouping_auto": { "count": 25, "total": 30, "rate": 0.83 },
    "action_auto":   { "count": 24, "total": 30, "rate": 0.80 },
    "escalated":     { "count": 2,  "total": 30, "rate": 0.07 }
  },
  "time_seconds": {
    "ai_median": 42,
    "human_wait_median": 1085
  },
  "tokens": {
    "total": 184300,
    "per_ticket_avg": 7680,
    "by_agent": { "request-access": 62100, "service-desk": 41200 }
  },
  "resolved_by_day": [ { "day": "Mon", "count": 12 } ]
}
```

`ai_median` and `human_wait_median` are reported separately and must never be
summed into a single figure (REQ-034). Blended, the human queue delay swamps the
AI time and the metric stops meaning anything.
